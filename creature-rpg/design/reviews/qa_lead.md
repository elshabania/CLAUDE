# QA Lead review: cross-document testability and consistency

Reviewer: QA Lead. Date: 2026-09-24. Scope: `creative_direction.md` (CD), `creatures.md` (CR), `systems.md` (SYS), `world.md` (WLD), `rendering_and_architecture.md` (RND), `release_character_gate.md` (RCG), checked against `ANCHORS.md` and `qa_plan.md` (QA).
Method: I read all six documents in full. I then cross-checked every id, number and rule that a test in `qa_plan.md` depends on. I recomputed the SYS worked examples §7.5, §16 and §17 by hand, and all of them reproduce. Name similarity was computed with a standard Jaro-Winkler script (prefix weight 0.1, max prefix 4) against the RCG §3.4 creature list. **No game code exists, so no test has been run.** Every finding below is a document-level finding.

**Severity:**
- **Blocker:** two documents give contradictory expected values for the same test, so tests cannot be written until one owner decides.
- **Major:** a test can be written, but some documented behaviour must be wrong, or an automated gate would fail by construction.
- **Minor:** wording, placeholder data or naming that needs aligning.

**Headline:** the six documents are individually strong. SYS in particular is implementation-ready, and its arithmetic is correct. However, **CD and WLD describe two different campaigns**: different zone order, trial types, attuned types, field-action unlocks, mandatory gates, rival count, unchosen-starter route and id scheme. Until that is reconciled, the quest-graph, obtainability, softlock and campaign-simulation tests (D-25, D-30…D-36, SIM-01…05, M-01…M-30) have no single oracle. **Recommendation:** the orchestrator names one campaign (see B-01) and the owners re-issue the affected tables before any Phase 2 content work starts.
